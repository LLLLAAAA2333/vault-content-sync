# 文本三方合并契约（0.4.0）

对应行为测试为 `tests/merge/contract.test.ts`。输入共同文本 B（可为 null）、本地 L、远端 R；模块不读取文件、网络、状态或 YAML。

## 输出与保真

`mergeText(B, L, R, limits?)` 返回带判别字段的联合类型：`merged` 含完整 text 和来源 changes；`conflict` 含冲突 regions；`stopped` 含 reason。失败分支没有 text，不能作为待写入版本。行范围为从 0 开始、右端不包含的 B 坐标；插入范围起止相同。成功来源为 local、remote 或 both，同时记录结果行范围。快捷路径可报告整个文档的来源，不承诺最小差异。

按含终止符的完整行比较：LF 和 CRLF 是内容的一部分，单独 CR 是普通字符。末行不补换行，空文本为零行。未改动行来自 B；替换/插入行逐字来自对应输入。不进行换行归一化、Unicode 规范化、Markdown/YAML 格式化。交换 L/R 得到相同结果文本和判断（来源标签对调）。

## 决策

资源检查优先，包括相同输入。L=R 直接接受共同结果（即使 B 缺失）；单边等于 B 接受另一边的原文。B 缺失且 L≠R 停止。

其余情况按完整行最长公共子序列定位两个版本相对 B 的改动区间：

- 同一 B 区间和完全相同替换只保留一次，来源 both；双方其他改动仍正常比较。
- 两个非空区间有交集则冲突；相邻、无交集的替换/删除允许合并。
- 两个插入在同一位置且不同则冲突；插入点在另一方替换/删除的闭区间内（含首尾边界）则冲突。
- 删除与修改相交时冲突。冲突返回所有相连的冲突区域，绝不返回暂存正文。

首版只接受可证明定位稳定的差异：若某个未匹配行在 B 和该侧文本中都出现，停止并报告 `ambiguous-alignment`。这包括重复行的删增、移动、部分重排，以及一些实际上可明确定位的编辑；不会将任何一种 LCS 的偶然选位当作证据。重复段落、空行、围栏可以完整匹配并保留；只改动其中非重复内容仍可合并。这是有意收窄的能力边界，不实现移动识别、Histogram、字符级或 YAML 字段合并。

证明范围：通过此检查意味着所有在两份文本中共有的行出现次数都被顺序匹配。若存在另一种匹配位置或另一种同长公共子序列，至少有一个共有行实例必须在当前匹配中被跳过，因此会被拒绝。此策略可能多拒绝，不以减少冲突为目标。

## 统一资源限制

每次任务只有一个预算对象，两个差异计算、定位检查、排序、重叠检查和结果组装共享计数；没有分块重置或失败后重试。

默认输入总量上限 1,572,864 UTF-16 单元（三个字符串载荷约 3 MiB）、总行片段 60,000、工作单位 8,000,000。工作单位覆盖输入单元扫描、行/映射遍历、整数相等比较及组装；不是毫秒承诺。先做总字符检查，再扫描分行并累计行数。行先驻留为整数 ID，避免长行在 LCS 内被反复按字符比较。文本载荷、行/映射/差异/输出数组以及 diff 库线性辅助数组由同一总量界定；这不是 JS 引擎 RSS 的精确硬上限。

阈值为首版桌面交互防护：约 3 MiB 输入载荷、最多六万行描述符、八百万单位纯计算，允许常见笔记，拒绝病态匹配；不是吞吐量基准。调用方只可调低限制以便测试或更保守运行。超限返回 `input-limit`、`line-limit`、`work-limit`，没有成功正文。同步层还保留每份原始文件 1 MiB、有效 UTF-8 和无 NUL 的接入限制。

## 同步边界与兼容

同步层调用前提取共享文本，调用后恢复本机 updated；仍用原始字节核验前提、条件写入、留存版本和恢复。新模块不包含 updated 策略。format 2 不变。模块停止时可归档读取到的原始版本并取得临时锁，但不得创建待执行意图、推进基线或改写两端内容。
