# WebDAV 同步

## 使用

1. 在插件设置中填写 WebDAV 文件夹地址、用户名与密码。外部地址要求 HTTPS。
2. 打开变更侧栏并点击「刷新变更」。点击冲突文件可以并排审查两端版本。普通 Markdown 支持逐段选择和手动编辑结果。
3. 对照结果后点击「提交结果」。非冲突文件可以通过「提交变更」或文件菜单中的「同步此文件」同步。
4. 从「更多操作 → 恢复未完成的提交」查看并确认待恢复文件；单文件提交只处理选定文件。

## 写入机制

提交会留存原始版本，在写入前重读有关文件，并在写入后检查两端共享内容。开始审查后若只有本地 Markdown 顶层 `updated` 变化，提交仍可保留该字段的新值。正文发生变化时，可从当前审查页刷新单个文件。

远端新建使用 `If-None-Match: *`。覆盖及删除使用带强 ETag 的 `If-Match`。插件不请求远端目录锁，也不会因条件失败而重试无条件写入。两端更新不是单一事务；中断可通过保存的恢复记录处理。服务器必须正确执行条件请求。目录列表不是原子快照。

恢复版本保存在本机 `.plain-sync/`，格式仍为 2。读取失败视为未知。没有共同版本时，插件不自动合并不同内容或推断删除。

## 独立验证

- `pnpm check`：格式、类型、社区 lint、构建与模块边界。
- `pnpm test`：纯计算、同步、恢复、认证、凭据和故障测试。
- `pnpm test:webdav`：独立 Apache mod_dav_fs + Basic 认证，验证实际协议、两个合成客户端、双向传输、合并与取舍、锁竞争、恢复及删除。
- `pnpm e2e`：原有隔离 Obsidian 全流程回归。
- `pnpm e2e:webdav`：真实 Apache 与独立 Obsidian 的上传、下载、冲突处理和主题截图。

Apache 工具默认使用 Homebrew 的 httpd；可用 `PLAIN_HTTPD` 和 `PLAIN_HTTPD_MODULES` 指定已安装的实现路径。配置、文档根目录、认证文件、客户端和 Obsidian profile 均位于本项目新建的 `runtime/apache-*` 下；只监听回环地址，退出后停止进程，不注册后台服务。证据放在被 Git 排除的 `artifacts/`。本轮没有使用日常笔记、真实凭据或外部服务器。
