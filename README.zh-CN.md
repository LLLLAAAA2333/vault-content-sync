# Vault Content Sync

[English](README.md)

WebDAV 内容核验与保守文本合并，面向 Obsidian 桌面端。

Vault Content Sync 把本地笔记库与指定 WebDAV 目录进行完整内容比较，按共同版本识别修改与冲突。Markdown 顶层 `updated` 仅保留本机，正文、其他属性和附件参与比较。

**已发布的 0.5.0 是实验版本：外部 WebDAV 仅开放只读预览。** 写入、冲突应用和中断恢复只在随附的本机隔离模拟服务中开放。默认不自动连接、不自动同步。现已有[公开社区页面](https://community.obsidian.md/plugins/vault-content-sync)，自动扫描处理见[逐项核对](docs/SCORECARD_REVIEW.md)。

0.5.0 新增设置页“测试连接”、精简的源代码管理侧栏和主编辑区只读比较标签页；侧栏冲突片段按需展开。

**当前工作区尚未发布：** 设置改为一个遮挡内容的密码框和“记住密码”开关。默认仅本次使用；开启后通过 Obsidian 在本机加密保存，不需要创建或选择密钥。缺失密码和 HTTP 401 直接提示认证问题，不再把整库显示为未核实。已发布的 0.5.0 附件不含这些改动。

当前开发构建中，主动清空已保存密码并离开输入框（或关闭设置）会清除保存引用；设置保存失败时明确提示并保留上次成功配置。操作失败会丢弃旧预览，需要重新核验后继续。

## 开发版 0.6.0

以上外部只读限制属于已发布的 0.5.0。当前未发布构建已加入真实 WebDAV 上传、下载、条件删除、采用本地/远端、保守文本合并和中断恢复。侧栏或设置中点击“验证并开启同步”：先在远端新建独立合成目录，验证独占目录锁、强版本标识、条件写入和中断保护；通过后仅开放本次连接，不自动同步笔记。重启或修改连接/凭据后重新验证。不支持所需能力的服务器保持仅预览。

界面按 Zed 的布局调整为顶部变更与工具栏、中间文件区、底部固定远端状态及操作。先核验、比较，再确认“同步全部”；文件菜单支持“同步此文件”。冲突单独选择本地、远端或合并；恢复未完成操作另行确认。此处没有 Git 提交消息和完整提交历史。

使用与边界见[真实 WebDAV 同步](docs/WEBDAV_SYNC.md)。集成测试使用独立 Apache mod_dav_fs 和合成库。每个实际服务仍须单独验证写入能力。

## 能做什么

- 按内容核验笔记和附件，不依靠修改时间推断覆盖方向。
- 用共同版本进行行级三方合并，保留原始换行、BOM 和未修改内容。
- 相邻独立替换可以合并；重叠编辑、边界插入或定位不可靠时停止。
- 写入路径具备前提核验、条件请求、原始版本留存和中断恢复。
- 读取失败视为未知；没有共同版本时不自动合并不同内容或推断删除。

## 安装与使用

需要 Obsidian 桌面端 **1.14.4 或更新版本**。当前仅在 macOS 实机验证；不支持移动端。

1. 在隔离测试库中通过社区页面安装；也可从 [GitHub Releases](https://github.com/LLLLAAAA2333/vault-content-sync/releases) 下载同一版本的 `main.js`、`manifest.json`、`styles.css`，放入**隔离测试库**的 `<配置目录>/plugins/vault-content-sync/`。默认配置目录是 `.obsidian`，自定义时以该库的实际配置目录为准。
2. 在 Obsidian 的社区插件设置中启用 Vault Content Sync，打开插件设置。
3. 填写已确认的 WebDAV **HTTPS 文件夹地址**，用户名和密码分别填写。服务要求账号时，使用您自己的服务账号；不需要 Vault Content Sync 账号，也没有付费功能。
4. 可先在插件设置中点击“测试连接”：只检查指定目录，15 秒超时、响应最多 64 KiB，不读取笔记或创建同步状态。点击侧栏 Vault Content Sync 图标，或运行“查看文件变化”（开发版；已发布 0.5.0 名为“完整核验并预览”），再点击刷新图标“核验内容”。首次运行只比较两端内容，不创建共同同步基线，也不修改笔记或远端文件。
5. 预览在左侧栏打开。“冲突 / 本地变更 / 远端变更”按组折叠，筛选图标展开文件名、路径和状态筛选。点击文件名，在主编辑区打开本地/远端只读比较；眼睛图标按需展开侧栏冲突片段，默认收起。文件操作在悬停、键盘聚焦或右键菜单中显示，连接测试在插件设置中，内容规则见下文。没有共同版本时明确显示两端内容预览，不推断具体冲突行。写入前需要通过服务器能力验证，再确认本次操作。

当前开发版刷新默认增量核验：插件加载后首轮完整读取；后续仍列出两端目录，本地文件标识/大小/高精度时间不变则复用哈希，远端通过条件 GET 确认不变后不再传输正文。每个远端文件仍有一次条件请求；缺失或弱版本标识、服务器忽略条件而返回正文时会完整读取。点击“更多操作 → 完整核验所有文件”，或运行同名命令，可强制重读所有文件。悬停结果摘要可查看复用项数和实际读取量。缓存仅驻留本次插件运行，不写入笔记库；重启后重新建立。仅测试连接不会读取笔记。已发布 0.5.0 仍采用完整读取。地址必须直接指向目标文件夹：插件不会跟随重定向，也不接受 URL 中的凭据、查询参数或片段。已发布 0.5.0 的密码在停用插件或重启后需重新输入。开发版填写密码后可开启“记住密码”，重启后继续使用；关闭时仅本次有效。密码框隐藏内容、禁止复制和剪切；修改已记住的密码后，离开输入框时保存。设置已接入宿主搜索，可用 WebDAV、username、password 等英文词查找。

内容规则：仅忽略 Markdown 顶层 `updated`；不重新格式化正文或其他属性。排除实际 Obsidian 配置目录、`.obsidian`、`.claudian`、`.git`、`.sync_state.json`、`.sync_trash`、`.DS_Store`、`.plain-sync`、`.trash` 及符号链接。历史版本与恢复内容保存在 `.plain-sync`，不自动清理。

## 开发与验证

Node.js 24、pnpm 10：

```sh
pnpm install --frozen-lockfile
pnpm check:release
pnpm test
pnpm demo
pnpm e2e
```

`pnpm build` 输出 `dist/vault-content-sync/`，包含 `main.js`、`manifest.json`、`styles.css` 及许可证。GitHub Release 仅附安装所需的三个文件，完整许可证内嵌 main.js，校验值列在发布说明中。插件 ID 为 `vault-content-sync`。`pnpm check:release` 同时检查发布字段、兼容版本、安装附件和内嵌许可证。`pnpm e2e` 仅在 macOS 的独立 Obsidian 配置和 `runtime/` 合成库内验证，不访问日常笔记库。

```text
src/       插件入口、同步引擎、原生界面和纯计算合并模块
tests/     行为契约、同步与恢复回归测试
tools/     构建、模拟服务、隔离演示和故障测试
docs/      当前设计、合并规则与验证结果
```

## 使用边界与数据

仅向用户配置的 WebDAV 地址发送请求，用于核验内容和执行已确认的同步操作；不收集遥测，不连接项目自有服务。地址、用户名保存在当前库的插件配置中；从配置文件加载的设置不能授予写入权限，包括回环地址。开发版另保存密码模式、不透明密钥引用和连接绑定，密码正文不写入 data.json。旧开发版记住的密码在升级后需核对地址并重新输入一次，新密钥记录与该目录和用户名绑定。默认密码仅保留在会话内；开启“记住密码”后由 Obsidian SecretStorage 在本机加密存储。系统加密不可用时提示本次使用，不降级保存明文。关闭开关时，如果存储可访问，会清空本插件创建的已保存值。更换服务器或用户名会清除当前密码绑定，需重新填写。遮挡和禁用复制属于界面行为，不用于防范其他已启用插件或控制应用的人。发布版 0.5.0 仍只支持会话密码。使用 Node.js 文件系统 API 完成流式核验、排他创建、硬链接留存与落盘保证；该 API 技术上具备访问系统其他文件的能力。正常插件操作使用当前笔记库，不扫描其他笔记库；实际配置目录（包括自定义名称）及默认排除目录不会作为笔记扫描或传输。服务器响应仅用于解析路径及文件内容，不执行其中的代码。

开发工具可操作显式指定的测试路径；测试写入限于 `runtime/` 合成数据。同步状态目录仍为 `.plain-sync/`、格式为 2，未因品牌更名改变；其中的原始版本和检查点不自动清理。格式 1 不自动迁移。

未通过目录锁及条件写入验证的服务只开放预览。尚不支持移动端、YAML 字段级合并、字符级合并、移动识别、目录重命名识别和历史自动清理。
